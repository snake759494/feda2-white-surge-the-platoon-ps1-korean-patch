# 기술 설명

## 디스크 구조
- 데이터 트랙 1개(MODE2/2352). 실행 파일 `FEDA2.EXE`(RAM 0x80010000, 헤더 0x800)와 데이터 파일을 씁니다.
- 빌드는 바뀐 파일의 섹터만 같은 자리에 다시 쓰고 EDC/ECC를 다시 계산합니다(`tools/disc.py`, `tools/cdsec.py`). 모든 파일이 원래 크기·위치에 들어가므로 디렉터리는 고치지 않습니다.

## 문자 인코딩과 글꼴
- 게임은 Shift-JIS 문자열을 씁니다. 한글 완성형 2,350자에 SJIS 1수준 한자 코드(0x889F~)를 하나씩 배정했습니다(`tools/hg.py`). 출력 루틴은 고치지 않았습니다.
- 글꼴은 고정 글꼴 + 장면별 글꼴 구조입니다.
  - 실행 파일의 고정 글리프 표(0x800997E0, 6바이트 × 294: 코드·열·행)는 가나·기호와 자주 쓰는 한자를 가리킵니다. 한자 칸을 비우고, 메뉴·전투 메시지에 많이 나오는 한글을 그 칸에 배정해 글꼴1 사본들(WINDATA·BTLMAP·SAYSUN·KODAIRA)에 그립니다.
  - 대본 블록마다 붙은 글꼴(최대 336자, 캠프 블록은 672자)과 코드표에는 그 장면에 쓰인 나머지 한글을 그립니다.
- 글리프는 12×16 칸 4bpp이며 나눔스퀘어 네오 Bold 14px로 그렸습니다.

## 대본
- `TXTDATA.TXT`: 이벤트·막간 대본 74블록(블록 19는 실행 파일 문자열용 글꼴). 블록 0x7E0부터 대본, 앞쪽이 글꼴과 코드표입니다(`tools/script.py`).
- `BATMSG.MSG`: 전투 대본 8블록과 전투용 글꼴.
- `BIN/KODAIRA.DAT` 블록 8~15: 캠프 대화. 블록 8·15는 0x109E0, 나머지는 0x191C0부터 대본입니다(`tools/camp.py`).
- `$N` 화자 줄과 `#` 머리 줄은 화면에 나오지 않는 주석이라 원문 그대로 둡니다. 한 줄 20자, 한 창 3줄을 넘지 않게 빈 줄을 흡수합니다(`tools/check.py`).

## 실행 파일 문자열
- 401종 문자열을 원래 자리에 넣습니다. 같은 문자열이 여러 곳에 있으면 모두 바꿉니다(`text/exe_ko.tsv`).
- 미션 조건 문구는 실행 파일 안에서 줄바꿈 코드로 여러 줄을 나눕니다.

## 그림 글자
- `tools/narr.py`: `TIM/TIMDATA.TIM`의 나레이션·게임 오버 문장 그림 33장(8bpp)과 엔딩 크레딧 역할명. 원래 글자 줄 위치를 찾아(`tools/narrband.py`) 지운 뒤, 갈무리 원래 크기 중 그림 폭에 맞는 가장 큰 크기 하나로 그 그림 전체를 씁니다. 좌우 10px 여백을 둡니다.
- `tools/title.py`: 타이틀·파일 메뉴 문구(KODAIRA 0x24A00, 0x2CA00, 4bpp).
- `tools/labels.py`: 캠프 장소·인물 이름표(KODAIRA 0x75800, 8bpp 256×416), 작전명 14종(KODAIRA 0xD8000, 같은 그림이 WINDATA·SAYSUN에도 있어 모두 바꿈), 상태창 「무장」 음각 라벨(SAYSUN).
- 영어 그림(PUSH START BUTTON, NOW LOADING, MISSION END, GAME OVER, SECTION/BATTLE, MISSION CONDITION, OPM 등)과 개발용 낙서 그림은 그대로 두었습니다.

## 검증 도구
- `tools/emu.py`, `tools/ctl.py`: DuckStation을 창 밖에 띄우고 GDB 원격 접속으로 메모리를 읽고 쓰며 키 입력을 보냅니다. 전투 결과 화면은 메모리의 적 HP를 0으로 바꿔 빨리 진행해 확인했습니다.
